# Level 7. 실전 개발 워크플로 (종합 프로젝트)

## 목표
- Level 1~6에서 익힌 명령어들을 조합해 실제 백엔드 개발·운영 현장의 시나리오를 마우스 없이 처음부터 끝까지 해결한다.
- 새로운 명령어를 무작정 추가하기보다 이미 손에 익은 도구(`find`, `rg`, `grep`, `awk`, `sort`, `uniq`, `ps`, `ss`, `kill`, `curl`, `git`, `tmux`)를 유기적으로 연결한다.

---

## 세션 구성 (각 15~20분)

### Session 7.1: 레거시/신규 Java 프로젝트 아키텍처 초고속 파악
- **시나리오**: 처음 인수인계받은 Spring 프로젝트(`playground/java-project`)의 전체 구조와 엔드포인트, 외부 연동 지점을 5분 안에 파악해야 한다.
- **수행 작업**:
  1. `find`와 `wc -l`로 전체 Java 소스 파일 개수와 설정 파일 목록 파악하기
  2. `rg`로 모든 REST API 엔드포인트(`@GetMapping`, `@PostMapping`, `@RequestMapping`) 목록 추출하기
  3. `@Transactional`이 붙은 서비스 메서드와 `TODO`/`FIXME` 기술 부채 지점 찾아 리포트 파일로 저장하기

### Session 7.2: 운영 장애 로그 분석 및 원인 코드 역추적
- **시나리오**: 주문/결제 서비스에서 간헐적 500/502 에러가 발생했다는 알림을 받았다. `playground/logs/`에서 원인을 찾아내고 해당 Java 소스 코드 위치를 특정해야 한다.
- **수행 작업**:
  1. `access.log`에서 HTTP 상태 코드가 `500` 이상인 요청들의 시간대, 경로, 건수를 `awk`, `sort`, `uniq -c`로 집계하기
  2. `app-2026-10-21.log`에서 `ERROR` 로그와 스택트레이스(`grep -C 3`)를 추출해 가장 많이 발생한 에러 코드 확인하기
  3. 해당 에러 코드를 던지는 Java 클래스와 줄 번호를 `rg`로 찾고 `sed`/`cat -n`으로 해당 메서드 코드 확인하기

### Session 7.3: 좀비/충돌 프로세스 정리 및 API 서버 기동·검증
- **시나리오**: 로컬 테스트 서버를 재기동하려는데 포트가 이미 사용 중이거나 응답이 느린 프로세스가 떠 있다.
- **수행 작업**:
  1. `ss -tulnp`와 `ps aux | grep`으로 포트(`18080`) 점유 프로세스의 PID 확인하기
  2. `kill`로 기존 프로세스를 안전하게 내리고 포트가 비었는지 재확인하기
  3. 새 서버를 백그라운드로 띄운 뒤 `curl -i`와 `curl -X POST`로 헬스체크 및 주문 API 정상 응답 검증하기

### Session 7.4: Git CLI와 파이프라인 조합 워크플로
- **시나리오**: 장애 원인이 된 설정값과 코드를 점검하고 변경 내역을 CLI에서 빠르게 리뷰한다.
- **수행 작업**:
  1. `git status -s`, `git diff`, `git log --oneline -n 5`로 저장소 변경 이력 확인하기
  2. `git log`와 `grep`을 조합해 특정 키워드가 포함된 커밋 찾기

### Session 7.5: `tmux` 관제 환경 구축 및 반복 점검 스크립트 자동화
- **시나리오**: 매번 수동으로 입력하던 에러 집계 + 서버 헬스체크 작업을 하나의 자동화 스크립트(`playground/scripts/daily-report.sh`)로 만들고 `tmux`에서 실행한다.
- **수행 작업**:
  1. 에러 건수 요약, 디스크/메모리 여유 공간 확인, API 헬스체크 결과를 출력하는 Bash 스크립트 작성하기
  2. `chmod +x`로 실행 권한을 부여하고 실행 결과를 로그 파일로 남기기
  3. 전체 커리큘럼 핵심 명령어 총정리 및 나만의 치트시트 완성하기
